What you actually pay for

Your bill is your hardware.

With no licence fee, cost comes down to how much RAM and NVMe you provision. The difference from an all-in-RAM store is where the values live.

How to size a node before you price it

Plug your key count and value size into your cloud provider's price sheet. We will size it with you on a demo call — these are the rules we use, not a quote.

All-in-RAM storeDRAM
RAM ≥ data
Every key and value held in memory, plus per-key overhead. RAM grows with the dataset.
VeltrixDBNVMe
RAM ≈ index + cache
NVMe holds the values. RAM holds the index — ~142 B/key measured at 5M keys with the native index (since v1.6; 168 B/key with the Go map), plus ~90 B/key for the ordered index unless disabled — plus whatever cache you choose (default 256 MB).
Per-key figures are from an engine benchmark at 5M keys; measure with your own key lengths. No billion-key run has been published. Get a sizing review for your workload →

Rules of thumb are generic. Your workload isn't.
