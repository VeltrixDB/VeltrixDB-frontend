Numbers we can reproduce.

Every figure on this page comes from a measured run, and each one states the conditions it was measured under. Raw results are in BENCHMARK_RESULTS.md in the repo. No projected numbers, no competitor numbers we did not measure. No other database has been run on the same hardware yet: the same-hardware harness (bench/compare) exists, but its Aerospike and ScyllaDB paths are only compile-checked.

Durable single-key writes: adaptive vs fixed group commit v1.12

Adaptive group commit is the default since v1.12 (--group-commit=adaptive). The flush window becomes an upper bound: a lone writer is synced at once, and concurrent writers are synced after an idle gap of about one fdatasync. Conditions: the device’s fdatasync cost is emulated (a sleep before the real sync), because macOS fsync returns at the drive cache. 15 ms window, 128 B values, each writer doing sequential durable Puts for 1.5 s.

At this size the quantized layouts are slower per query than float32, because they re-rank candidates against the full vectors read back from the VLog. Active Development · September–October 2026

What we're working on in the engine.

All of this has shipped, in v1.6, v1.7, v1.11 and v1.12 (v1.13 was a documentation release; v1.15 is the latest). The experimental and investigating items ship as opt-in switches. Each item lists what we measured and under which conditions, including the result that did not go our way. No dates are promised.

01
Shipped
Index
Off-heap native index
On cgo builds (macOS included, and the Docker image) each shard’s index lives in a C++ table off the Go heap: 64 B records, 8 B tag|position slots, a per-shard key arena. Go’s garbage collector no longer scans it. The cost is ~19 ns more per cache-miss lookup, and large key counts need vm.max_map_count ≥ 262144. VELTRIXDB_INDEX=map opts out. Since v1.6.

02
Shipped
Durability
Binary WAL
A 48-byte little-endian header and a CRC32C over the whole record. It fixes a real bug: keys containing | or a newline truncated text-WAL replay, so acknowledged writes could be lost on a crash restart. The reader accepts binary and legacy text records mixed; --wal-format=text is the rollback. Since v1.6.

faster replay
4× faster encode

Shipped
Write path
No skiplist re-insert on overwrite
Overwriting a live key no longer re-inserts it into the ordered index; only absent or tombstoned keys are inserted. Measured on server batch writes (8 clients × 1024-key MPUT, 1M-key space, macOS): 1.45M → 3.54M keys/s, P99 9.6 → 4.2 ms.

04

Network
C++ network front-end (--net=cpp)
Opt-in, standalone mode only, binary PUT/GET/DEL/PING/MPUT/MGET only. On a 4-CPU CI runner it cut read P50 by ~45% (154 vs 286 µs) and poll read throughput rose 10%, but read P99 got worse (~3.0 vs 1.8 ms), batch writes were ~12% lower and io_uring did not beat poll. It is not faster overall. Since then, reads that need a disk read are finished off the event loop (deferred reads); that change has not been re-measured yet.

Storage
Bisecting the C++ storage layer
On the same runner, the C++ storage extras all on (io_uring write bridge + SQPOLL, batch engine, native index) measured 1.12M keys/s batch writes vs 1.77M with them off. Durability
Adaptive group commit
The WAL and VLog flush windows are now upper bounds, not waits. A lone writer is synced at once; concurrent writers share one fdatasync after an idle gap of about one sync. With an emulated 300 µs sync and the 15 ms default window (macOS), one writer’s P50 went 16.0 → 0.45 ms and 64 writers 4.0K → 37.5K writes/s at the same writes per sync. --group-commit=fixed restores the old behaviour.
